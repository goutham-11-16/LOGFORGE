# LOGFORGE: Universal Log Pre-processing Framework (ULPF)
## System Architecture & Technical Specification (SIH26156)

---

### 1. Executive Summary
Modern enterprise perimeters are inundated with heterogeneous log streams generated by firewalls, routers, switches, VPN gateways, and intrusion detection systems. These devices emit logs in conflicting, proprietary, or semi-structured formats (Syslog RFC 3164/5424, ArcSight CEF, IBM QRadar LEEF, Suricata EVE JSON, Cisco ASA key-value, and CSV). 

**LOGFORGE** is a Universal Log Pre-processing Framework designed to ingest, parse, normalize, and standardize any perimeter device log into a unified **Universal Event Schema**. Crucially, LOGFORGE enforces **lossless processing**, preserving 100% of the raw event for strict forensic audit and legal compliance while outputting AI/ML-ready datasets for next-generation SIEMs and Data Lakes.

### 3. Core Engine Components

#### A. Intelligent Format Detection & Parser Registry
The Parser Registry employs a multi-stage confidence scoring matrix. When raw lines arrive, candidate parsers evaluate structural syntax tokens (e.g., `<PRI>` headers for Syslog, `CEF:` and `LEEF:` magic bytes, valid JSON brackets, delimited comma ratios, and Cisco `%ASA-` message identifiers). The parser with the highest confidence score (>0.80) is dynamically invoked.

#### B. Unified Normalization Engine
Heterogeneous perimeter vendors represent identical networking concepts with divergent terminology. LOGFORGE maps these fields into a canonical taxonomy:
* **IP Addresses:** `src`, `src_ip`, `sourceAddress`, `sourceIP`, `c-ip` $\rightarrow$ `network.source_ip`.
* **Actions:** `permit`, `pass`, `built`, `allow` $\rightarrow$ `allow`; `block`, `drop`, `deny`, `teardown` $\rightarrow$ `deny`.
* **Protocols:** Protocol numbers (6, 17, 1) and case variants $\rightarrow$ `TCP`, `UDP`, `ICMP`.
* **Severities:** Syslog 0-7 priority levels and CEF 0-10 numeric ratings $\rightarrow$ `critical`, `high`, `medium`, `low`, `informational`.

#### C. Lossless Retention & Forensic Traceability
Every generated `UniversalEvent` includes:
1. `raw_event`: The uncompressed, unmodified original log line.
2. `event_id`: A cryptographically collision-resistant UUID tracking the record through SIEM pipelines.
3. `metadata`: Audit metadata including the parser used, source format detected, confidence score, and processing timestamp.

---

### 4. Storage & Air-Gapped Operation
To support deployment in air-gapped military, government, and critical national infrastructure environments:
* **Zero Cloud Dependency:** The engine runs entirely on local infrastructure with zero internet calls.
* **Persistent SQLite with WAL:** Utilizes Write-Ahead Logging (`PRAGMA journal_mode = WAL`) and normal synchronization for ACID persistence and high-throughput ingestion.
* **Indexed Search:** Dedicated B-Tree indexes on `timestamp`, `source_ip`, `destination_ip`, `protocol`, `action`, and `severity` enable sub-millisecond filtering across hundreds of thousands of events.

---

### 5. Production Scalability & Big Data Path
While the standalone prototype processes thousands of events per second on commodity hardware, the architecture is engineered for horizontal scale:
* **Stateless Parsing Workers:** Parsers maintain zero shared state; ingestion pipelines can be partitioned across Celery, Kafka partitions, or Apache Flink workers.
* **Downstream Delivery:** Export streams are formatted directly for ClickHouse, Snowflake, Elasticsearch, and Parquet data lakes.
